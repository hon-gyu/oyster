# Start here

A vault that exercises every feature of the Oystermark language server. Open
this directory as the workspace root — `oysterlsp.json` sits beside this note —
and work down the list.

## Features

- Go to definition: follow any link; the inline-span one lands mid-line
  - [[links]]
- Hover: preview the target of a link without leaving the note
  - [[links]]
- Find references: from a heading, every link in the vault that resolves to it
  - [[anchors]]
- Completion: note names after `[[`, anchors after `#`
  - [[links]]
- Diagnostics: unresolved links, unresolved fragments, duplicate ids, unknown
  commands
  - [[diagnostics]]
- Code action: create the note behind an unresolved link
  - [[diagnostics]]
- Document outline: headings and attribute ids, as a tree
  - [[anchors]]
- Code lens: how many links land on a heading, and on the note
  - [[hints-and-lenses]]
- Inlay hints: the direction and distance of an intra-note link's target
  - [[hints-and-lenses]]
- Rename: the file moves and inbound links are rewritten
  - [[rename-me]]
- Daily notes: open today's, or jump between existing ones
  - [[journal-index]]
- Command block: commands as clickable lenses in the note
  - [[command-panel]]
- Table of contents: insert one, and get told when it goes stale
  - [[toc]]

## Reading order

Two notes are worth reading before the rest: [[anchors]] defines what can be
linked to, [[links]] links to all of it.

[[command-panel]] is generated by dune from the server's command catalogue, so
it lists every command that exists today. Everything else here is written by
hand.

## Configuration

`oysterlsp.json` sets daily notes to `journal/YYYY-MM-DD`. The two
`unresolvedFragment` keys are at their default `fallback`; switching either to
`strict` changes what [[diagnostics]] and [[links]] show, which is the quickest
way to see configuration take effect.
